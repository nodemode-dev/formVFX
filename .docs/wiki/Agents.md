# Agents

formvfx exposes all of its commands to agents. Changes they make appear in the window live and are ordinary undo steps.

## In the terminal dock

The terminal dock (Cmd or Ctrl+J) sits under the panels, or at their right from the side button in its head, remembers whether it was open, and holds tabs: shells in formvfx's agent workspace (`~/Formvfx/agent-workspace`), Claude Code tabs and one Chat tab. The robot button starts Claude Code there, and More agents starts Codex, Cursor or Antigravity (Google's `agy` program) when installed; Codex and Cursor find the `formvfx` MCP server and the `formvfx-harness` skill in the folder, and an Antigravity tab gets its own MCP entry in the folder's `.agents/mcp_config.json` while it is open. formvfx looks for the four programs on its own PATH, in their usual install folders and on your shell's PATH, and a program it cannot find or start is listed with where it looked and how to install it. Agents started with the Claude Code, Codex, Cursor and Antigravity buttons are trusted and never see a permission prompt; a program you start yourself in a shell tab asks like any outside agent. Tabs keep running while the dock is hidden, and Restart runs a tab's program again.

Window > Start Claude Code (Shift+Cmd or Ctrl+J) opens the dock with a Claude Code tab in one step; the line under the dock sends it a request in plain words. The title bar's Agent button has the same entries.

## The Chat tab

Window > Chat with Claude (Alt+Cmd or Ctrl+J) opens a chat that answers in formatted text and shows each formvfx tool it uses as it goes, for people who would rather not use a terminal. Its bar shows how much of Claude's memory the conversation uses and what it has cost, stops a reply, starts a new chat, continues the conversation in a Claude Code tab (Open in Claude Code) or brings one in from a Claude Code tab (From Claude Code...). It needs Claude Code installed and signed in; its changes are undo steps like any other.

## From this repository or anywhere

- In the repository, `.mcp.json` (Claude Code), `.codex/config.toml` (Codex) and `.cursor/mcp.json` (Cursor) run `./formvfx mcp`.
- `./formvfx agents install` (or Install in the Agents panel) adds the MCP server and the skill to your Claude Code, Codex and Cursor setup and the MCP server to Antigravity's (`~/.gemini/config/mcp_config.json`), backing up any file it changes.
- The first change from an outside agent asks in the formvfx window, naming the agent and what it asked for: Deny, Allow once (that one call; the next change asks again) or Always allow for that agent (remembered). The question appears above any open dialog, waits its turn when another is open, and closes by itself when the agent goes away. Reads never ask. Only the window can answer, and Forget all in the Agents panel clears the remembered list. `FORMVFX_AGENTS=deny` on the engine refuses every agent's changes without asking: outside agents, including ones you chose Always allow for, and formvfx's own Chat and its Claude Code, Codex, Cursor and Antigravity tabs. You still edit in the window, agents can still read, and no setting skips the question. With no window open an outside agent's changes are refused, so open formvfx first, or start the agent from the Claude Code, Codex, Cursor or Antigravity button in formvfx.

## The tools

`status`, `list_commands`, `describe_command`, `execute`, `batch`, `get_comp`, `get_layer`, `get_property`, `set_property`, `set_keyframes`, `apply_effect`, `list_effects`, `text_preset`, `shapes_from_svg`, `planar_track`, `object_matte`, `render_frame`, `contact_sheet`, `render`, `dynamic_link`, `project`, `import_files`, `history`, `ui`, `wait`, `run_script`, `guide`, `extensions_list`, `extension_command`. The full reference is `.claude/skills/formvfx-harness/references/tools.md`.

## Command line

```bash
./formvfx state
./formvfx commands layer.new
./formvfx describe layer.newText
./formvfx exec comp.new '{"name": "Promo", "width": 1920, "height": 1080, "duration": 6}'
./formvfx batch '[{"command": "layer.newText", "params": {"text": "Hello"}}]'
./formvfx frame out.png --time 1.5
```

The command line counts as an outside agent. `state`, `commands`, `describe`, `frame` and every command that only reads never ask. `exec` or `batch` with a command that changes the project, and `render`, ask once in the formvfx window like any outside agent (Allow Always covers later runs). They fail with the reason when no window is open or when `FORMVFX_AGENTS=deny` is set, so a script that changes the project needs the formvfx window open and answered first.

## The skill

`.claude/skills/formvfx-harness` (mirrored to `.agents/skills`) teaches agents the model, the build loop and each area of the application, with recipes that were run against the engine. Its references for commands, effects, property paths and tools are generated by `./formvfx agents sync` from the engine itself.
