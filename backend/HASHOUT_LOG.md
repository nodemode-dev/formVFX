# backend · HASHOUT_LOG

Living context for the engine service. Code carries almost no comments; the reasoning lives here.

## Shape

- `app/engine/host.py` owns the one `fvx_core.Engine` on a dedicated thread (the engine is not `Send`). Everything that touches it is submitted as a callable to that thread; a 100 ms tick drains engine events, polls background jobs and autosaves.
- Frame, audio and thumbnail renders are built on the engine thread as `FrameJob` / `AudioJob` / `ThumbJob` snapshots (an `Arc` of the project) and run on thread pools with the GIL released, so rendering never blocks editing.
- `changed` events go to every window over the bus with `revision`, `edited` (did the project change, which purges RAM previews) and `source`. Commands that do not bump the revision (time.set, layer.select) still publish with `edited: false` so every window follows the time and selection.
- `app/engine/rpc.py` is the single JSON-RPC dispatcher behind `/api/rpc`, the `/api/live` socket, the MCP tools and the CLI. `engine.batch` takes `$N.key` references counted from 1.

## Agent substrate

- `app/agent/tools.py`: the MCP tools and the guide texts. The tool catalogue is the source the harness skill's `references/tools.md` is generated from (`./formvfx agents sync`).
- Consent (`app/agent/consent.py`): a per-boot token in the Terminal panel's environment marks trusted agents; others ask once in a window (Allow, Allow Always, Don't Allow) unless `FORMVFX_AGENTS` is `allow` or `deny`. Reads never ask.
- `app/agent/workspace.py` writes the agent workspace (`~/Formvfx/agent-workspace`): CLAUDE.md, AGENTS.md, MCP configs for the three clients, a `formvfx` shim on PATH and the harness skill.
- `app/agent/stdio.py` is the stdio relay `./formvfx mcp` runs: it finds the engine (FORMVFX_URL, the discovery record, the default port) and starts one headless when none answers.

## Facts that bit

- Unknown parameters in `execute` are ignored by the engine, not rejected.
- `prop.set` takes menu values as 0-based indices only; option names fail.
- Giving a vec3 transform property two values sets z to 0 (scale z 0 matters once a layer turns 3D).
- Keyframe commands (`prop.addKey`, `keys.set`, `keys.select`) take layer seconds; `set_keyframes` converts and snaps.
- `layer.newText` positions are baselines.

- Query commands (`_QUERY_IDS` in `app/agent/consent.py`) never touch the revision; when the interface sends one, `rpc.execute` also skips `host.note`, so viewer polling (`track.status`, `puppet.info`) stays out of the Activity list. Agent queries are still logged.

- `/api/peaks/{item}` (0.4.0): the engine thread only builds the job (`peaks_job`, cheap); the summary runs on `host.jobs`. Results are kept by the job's key (footage path, or comp id and revision) in an LRU of 48, and concurrent requests for one key share one task. 204 when the item has no audio.
- `ui.flowchart` is a read RPC; agents get the same graph through `get_comp {flowchart: true}` (layers and effects included).

- Multi-frame rendering (0.5.0, `app/engine/performance.py`): `performance.json` in the data folder keeps `multiFrame` and `reservedCores` (default 0). At start the engine sets `RAYON_NUM_THREADS` to the cores left (unless the variable is already set), which also sizes the Render Queue's batches; that part applies at the next start. Previews follow at once: `/api/viewer` range requests keep up to `host.preview_frames` frame jobs in flight and send them in order; a new single-frame request cancels the window and the range resumes from its first unsent frame. Keep `reservedCores` at 0 by default: one reserved core on a two-core machine halved single-frame speed, because every frame's own pixel work shares the same rayon pool.
- `/api/snapshot.png` serves the Take Snapshot image (`snapshot()` on the core); 204 when there is none.
- `render_frame {view}` renders a 3D comp from a 3D view through the frame job's `view3d` parameter.

- Text preset library (0.6.0, `app/engine/text_presets.py`): `presets/text-animators.json` is generated by `setup/text_presets.py` (edit the generator, then `./formvfx presets`; CI runs `--check`). It is read once from the repository root, or from the frozen bundle's `presets` folder (`--add-data presets` in both freeze scripts). `text.library` lists it without animators; `text.applyLibraryPreset` sends the whole preset object to the core's `apply_text_preset`, after turning `#n` layer references into ids through `comp.info`, because the core only takes ids and names.
- Edits that are not registry commands (`apply_text_preset`, `paste_svg`) go through `_native_edit`: the call is made with `touches=True` so the revision moves and the interface pulls, and `host.note` records it in Activity like a command.
- Square-shaped range selectors do not move with `offset`: a library reveal keys `start` (in) or `end` (out) instead. Ramp Up with offset -100 to 100 reveals; Ramp Down with the same keys hides.
