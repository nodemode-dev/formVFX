# fvx-core · HASHOUT_LOG

Living context for formvfx's compositing engine. Code carries almost no comments; the reasoning lives here.

## What it is

fvx-core is formvfx's compositing engine, written for formvfx in Rust and loaded by the engine service as the `fvx_core` Python extension. Standard algorithms are written from their definitions. It saves `.fvxproj` and reads `.ecproj` and `.ecprojx` projects saved by earlier formvfx releases as imports, never writing them.

## Shape

- **One `Arc<Project>`.** The engine keeps the project behind an `Arc`; a command clones it on write (`Arc::make_mut`). Undo steps are the previous `Arc`s (300 kept), so a step costs only the parts a command changed, and frame, audio, thumbnail and peaks jobs take an `Arc` snapshot and render off the engine thread with the GIL released.
- **Undo merging.** A command can carry a merge key (a drag inside a gesture, or `merge_hint` such as `text-<layer>` while typing); consecutive commands with the same key make one step. `end_gesture` and any other command clear it.
- **Commands are a table.** `registry.rs` lists every id with its label, menu, parameter schema and kind. `Undo` commands snapshot; `Plain` change state without undo (time, selection, viewer); `Query` only read; `Front` are handled by the interface (the engine returns a `frontend` event); `Todo` are ids the interface already shows that the engine does not do yet, and they answer with a sentence ("... is not in formvfx yet") instead of failing silently. Ids and parameter names stay stable from release to release, so the interface, the MCP tools and the harness references move only when a command is added.
- **`engine.batch`.** Steps run in order inside one undo step; `"$N.key"` strings (counted from 1) are replaced by a value from step N's result, so an agent can create a layer and key it in one call.

## Model

- **Time** is seconds as `f64` everywhere. Keyframes live in layer time (comp time minus the layer's start, scaled by stretch), so moving or stretching a layer moves its keys with it, as in After Effects. `.ecproj` ticks (254,016,000,000 per second) are converted on import.
- **One property tree per layer.** Every property is a `Prop` node with a uid and a match name; groups (transform, masks, effects, contents, text, audio) are nodes too. Paths address it the way the commands do: `transform/position`, `masks/#1/feather`, `effects/#2/radius`, `contents/Rectangle 1/fill/color`. The interface's Timeline twirls and Effect Controls read the tree through `ui_state({trees})`.
- **Keyframes** carry interpolation in and out (linear, Bezier, hold), temporal eases as speed and influence (After Effects' model; easy ease is influence 33.3 at speed 0), and spatial in and out tangents for position-like values. Spatial paths get auto tangents unless set (along the line from the previous key to the next, each side a third of it weighted by the distance to that neighbour), and an arc-length table so speed is even along the curve.
- **Values** are a small enum (number, vector, colour, path, text document, bool, enum index); interpolation is per type: numbers, vectors and colours lerp per channel as stored, paths lerp vertex by vertex when the counts match and hold otherwise, text documents hold.
- **`.fvxproj`** is the serde form of `Project` with `format: "formvfx.project/1"` at the top, pretty-printed JSON, so a project diffs well in git.

## Renderer

- **Float premultiplied RGBA** on the CPU (`f32` per channel), rows in parallel with rayon. A layer is rendered at its own size, effects run on that buffer, then it is warped into the comp through its full matrix.
- **Warps.** A 2D layer is an affine map; a 3D layer under a camera is a homography of its plane. Sampling is bilinear, and when an affine map shrinks the layer below half size it is halved (box filtered) until it is not, and sampled from that level, which keeps scaled-down text and footage from aliasing.
- **3D.** Each run of adjacent 3D layers is sorted back to front by the camera-space depth of its anchor point; a 2D layer between them ends the run and keeps its stacking position, as in After Effects. Cameras default to orient towards the point of interest. Lights are carried in the model and the interface but not shaded yet.
- **Blend modes** are the 39 of the interface's list, each as a function on unpremultiplied colour, plus Dissolve and Dancing Dissolve as per-pixel hashes on opacity (Dancing hashes the frame time too).
- **Masks** are filled with tiny-skia into a coverage buffer, grown by `expansion` (the coverage of a stroke twice the expansion wide, combined by max) or shrunk (multiplied by one minus that stroke), blurred by `feather` (a Gaussian with sigma half the feather), and combined by mode in stacking order; `inverted` flips the coverage before the mode.
- **Track mattes** render the matte layer as a tile with its opacity and multiply the layer by its alpha or luma (inverted or not); the matte layer itself shows or hides by its own video switch, as in After Effects since any layer can be a matte.
- **Motion blur** averages subframes across the shutter angle and phase from Composition Settings (180 and -90 by default, 16 samples, at most 64), only for layers with the motion blur switch when the comp switch is on and the render is not a draft.
- **Shapes** are evaluated as a list of operations per group: paths are collected, operators (Trim Paths, Offset, Pucker and Bloat, Twist, Zig Zag, Round Corners) rewrite them, then each fill and stroke paints what is above it, in order. Trim Paths measures with kurbo's arc lengths.
- **Text** is shaped with rustybuzz on a font found through fontdb (the family and style asked for, then the fallbacks in `render/text.rs`), and drawn as outlines through tiny-skia, so text stays sharp at any scale.

## Footage and audio

- Stills decode with the `image` crate. Video and audio go through the FFmpeg program when it is on the PATH (or `FORMVFX_FFMPEG`): `ffprobe` for size, rate, duration and audio streams; a decoder process per open clip streams raw RGBA frames, and seeking backwards or far forwards restarts it at the new time. Decoded frames sit in an LRU cache with a 1 GB budget.
- FFmpeg is a separate program, never linked, so its licence does not reach formvfx's binaries.
- Audio is decoded once per clip to `f32le` stereo at the project's sample rate and mixed per layer with its levels; peaks for the Timeline waveforms are 200 bins per second.

## Render Queue

- H.264, HEVC, ProRes 422 HQ, WebM (VP9) and GIF are FFmpeg encodes fed raw RGBA frames through a pipe (the comp's audio, mixed to a WAV first, as a second input); PNG, JPEG and TIFF sequences and WAV are written by the engine. `[####]` in a path is the frame number. Without FFmpeg the movie formats refuse with a sentence that names the ones that still work.

## Effects

- Every effect is written for formvfx, a parameter list plus a function from the layer buffer to the result (`effects/mod.rs`); 44 through 0.15.0, 281 from 0.16.0. Ids are `fx.<category>.<name>` and stay stable; `.ecproj` effects from earlier formvfx releases map onto them on import.
- Curl Noise is the same algorithm as formvfx's 0.7.0 Curl Noise Generator (fractal Perlin noise, its curl as a velocity grid, a line integral convolution), rewritten for this engine's buffers.

## Import

- `.ecproj` (JSON) and `.ecprojx` (the same document as XML, one element per value: `obj` with `m n="key"` members, `arr`, `str`, `num`, `bool`, `null`) are read and converted, never written. `engine/xmldoc.rs` is a small reader for that XML form. Items, comps, layers, switches, parenting, blend modes, track mattes, masks, transform keys, shape contents, text and the effects the engine has come across; anything that does not map is listed in an "Import notes" folder comment.
- Saving an imported project asks for a new `.fvxproj` path; a save to an `.ecproj` path is refused.

## Expressions (0.12.0)

- `src/expr` is formvfx's own interpreter for After Effects expressions, not a JavaScript engine crate: a lexer, a parser to an AST (`Arc`, so parsed programs are cached once per text and shared by every render thread) and a tree-walking evaluator. Vector maths is native to the operators (`value + [10, 0]`, `[1, 2] * 2`, a scalar added to an array goes to its first component), so no rewrite step sits before evaluation.
- The language: `var`, `let`, `const`, destructuring, functions, arrows, closures, `if`, `for`, `for of`, `for in`, `while`, `do`, `switch`, labels, `try`, `throw`, template strings, objects, arrays with their usual methods, strings, numbers (`toFixed`, JavaScript number formatting), `Math`, `JSON`. Classes and generators answer with a sentence; regular expressions arrived in 0.22.0. The last evaluated statement is the result. A run is capped at 4 million steps so an endless loop becomes an error, not a hung render.
- The object model (`host.rs`): `time`, `value`, `thisComp`, `thisLayer`, `thisProperty`, `comp()`, layers by name, index or relative index, transform shortcuts, `effect()`, `mask()`, `content()`, `text.sourceText`, markers, keys, `toComp`, `fromComp`, `toWorld`, `fromWorld`, `sourceRectAtTime`; property methods `valueAtTime`, `velocity`, `speed`, `wiggle`, `temporalWiggle`, `smooth`, `loopIn`, `loopOut` and their Duration forms, `key`, `nearestKey`; the helpers `linear`, `ease`, `easeIn`, `easeOut`, `clamp`, vector maths, `random`, `gaussRandom`, `seedRandom`, `noise`, time and colour conversions, `posterizeTime`, `createPath`. Unqualified names fall back to the property's methods, then the layer's members, as After Effects allows.
- A property reads its own pre-expression value; any other property is read after its expression. Expressions reading each other in a loop all report an error and fall back to their keyframed values; a property reading itself (through `toComp`, say) gets its pre-expression value silently. `wiggle` and `random` are seeded by layer id, property uid and frame, so frames render identically on every thread.
- Errors never break a render: the property falls back to its keyframed value. `expr.errors` lists them, `prop.setExpression` returns the error of the text it set, and the Timeline's expression row turns red with the message as its tooltip. `ease`, `easeIn`, `easeOut` and the loop types follow After Effects' definitions: 28 deterministic expressions baked to keyframes were checked value by value.
- Expression Controls (`effects/controls.rs`): Slider, Point, 3D Point, Angle, Checkbox, Color, Layer and Dropdown Menu (items edited with `effect.editDropdown`); they render nothing and do not send a layer down the effect path. Checkbox reads as 1 or 0 and Dropdown as a 1-based index, as in After Effects.

## Text layout and animation (0.13.0)

- **Layout lives in `render/layout.rs`.** `layout_with(doc, mods)` replaced the single-style layout that sat in `render/text.rs` through 0.12.1 (one font, one size, one tracking for the whole text; see that file at c7ad563). The new one resolves a style per character (`TextDoc::style_at`: the document's style with any `StyleRun` over it), splits each line into runs of equal font, size, features and scale, shapes each run with rustybuzz and continues one pen across them. Paragraphs come from line breaks; paragraph text wraps at spaces against the box width minus indents, the first line of a paragraph takes `indentFirst`, `justifyLeft`, `justifyCenter` and `justifyRight` spread the spare width over the spaces of every line but a paragraph's last, `justifyAll` over every line. Auto leading is 120% of the largest size on the line. Font data is copied once per face into a cache, so several faces can be shaped in one layout without nested closures.
- **Character styles.** `layer.setText` with `range: [start, end]` adds a `StyleRun` instead of changing the document; paragraph attributes still apply to the whole text. Runs are clipped when the text gets shorter.
- **OpenType.** Features are tags in `TextDoc.features` (`-tag` turns one off) and per run; `layer.setText` maps the After Effects names (`discretionaryLigatures` dlig, `stylisticSets` ss01 to ss20, `fractions` frac, `figureStyle`, `figureWidth` and the rest) onto tags, `ligatures: false` adds `-liga -clig`, `kerning: 0` adds `-kern`. Small caps use the font's `smcp` when it has one and otherwise fake it (uppercase at 75%); superscript and subscript use `sups` and `subs` or fake them (58.3% size, a third of the size up or down). `text.fontFeatures` reads the GSUB and GPOS feature lists.
- **Variable fonts.** `TextDoc.variations` (`layer.setText {variations: {wght: 700}}`) is applied to the face before shaping and outlining; the outline cache key includes a hash of the variation values.
- **Animators** (`render/textanim.rs`) follow After Effects' model. Each animator has properties and selectors; selectors give every character a selection in -1 to 1 per dimension, combined in order by their Mode (Add, Subtract, Intersect, Min, Max, Difference; a first selector in Subtract, Intersect or Min starts from full). Units are characters, characters without spaces, words or lines from the first layout. Range: Start, End and Offset in percent of the units or in unit indices; Square gives the overlap of the unit with the range, softened toward a hard step as Smoothness falls; Ramp Up and Ramp Down, Triangle, Round and Smooth are evaluated at the unit's centre; Ease High and Ease Low bend the result through a cubic with end slopes 1 minus each ease; Randomize Order permutes units by a seeded shuffle; Amount scales. Wiggly: three octaves of value noise per unit and per dimension (shared when Lock Dimensions is on), mixed with one shared noise by Correlation, between Min and Max Amount, Wiggles/Second and the two phases moving it. Expression: Amount is evaluated per unit with `textIndex` (1-based), `textTotal` and `selectorValue` (the selection so far, 0 to 100) available, and replaces the selection; `random()` there is seeded per unit.
- **Applying animator properties.** Position, anchor, skew, rotation, line spacing, stroke width and blur add the value times the selection; scale and the opacities multiply by 1 plus (value/100 minus 1) times the selection; colours move toward the animator colour by the selection times its alpha; hue, saturation and brightness work in HSB. Tracking and Character Offset or Value change the characters, so they are applied before a second layout; Character Offset with Preserve Case & Digits cycles within a-z, A-Z and 0-9. A variable font axis property moves its axis from the text's value toward the property's value by the selection, re-outlining that glyph.
- **Per-character transforms.** The anchor of a character is the middle of its advance on its baseline; Anchor Point Grouping by word, line or all uses the middle of that span, and Grouping Alignment moves it by percent of the span width and of the size. A character is drawn through base x animator x translate(-anchor), where base is the anchor's place, or with a path the point on the path and its tangent.
- **Text on a path.** Path Options > Path names a mask by index (the interface lists the masks); that mask stops masking the layer. The path is flattened and measured once per frame; Left, Center and Right place the line from First Margin, between the margins, or ending at Last Margin; Force Alignment spreads the characters between the margins (evenly around a closed path); Reverse Path and Perpendicular To Path do what they say; later lines sit their leading further out.
- **Per-character 3D.** `layer.enablePerChar3D` turns the layer 3D, sets the flag and gives existing Rotation properties X and Y companions. Each character then carries a 4x4 matrix and is projected through the camera on its own, sorted back to front by the depth of its anchor; effects run on the comp-sized result.
- **Blur** is per character: blurred characters are drawn into their own buffer, blurred with the box Gaussian, and laid over the others.
- **Projective vector rasterizing.** `vector::rasterize` now flattens paths and projects the points when the matrix is not affine, scaling strokes by the local area scale; tiny-skia only takes affine transforms, so 3D vector layers were drawn without perspective before.
- **Presets.** `presets/text-animators.json` is compiled into the engine; `text.applyLibraryPreset` (also the Python `apply_text_preset`) builds the animators of one preset at the current time, one undo step; key times are seconds from that time, `ease: true` gives easy-ease keys, `set` paths that the selector does not have (a range-selector path on a wiggly selector) are skipped. `layer.applyTextPreset` maps the eight short names onto library presets (Bounce In Words is Bounce In Characters by word).
- **Timeline kinds.** The tree now marks a group as `indexed` when it is an item of an indexed list (an animator, a selector, a mask, an effect, a shape item), which is what the Timeline offers Rename, Duplicate and Delete on; the lists themselves carry no kind.
- **Import.** `.ecproj` text layers bring their Path Options, More Options, Per-character 3D and their animators with selectors and keys.

## Shapes (0.14.0)

- **Operators act on paths above them and on the paints above them**, as in After Effects (a Trim Paths under a Stroke trims the stroke): `operate()` in `render/shapes.rs` rewrites `out.paths` and every collected op's paths with the same function. Merge Paths is the exception: it replaces the paths with the merged result and drops the paints above it in the group (they would paint the unmerged paths), and `shape.add` puts a Fill under it, as After Effects' Add menu does.
- **Merge Paths and Offset Paths** flatten to polygons (tolerance scaled to the size, 0.05 to 0.5 px) and use `i_overlay`: Merge is a non-zero union of everything, Add a union, Subtract the topmost path minus the rest, Intersect and Exclude Intersections (xor) likewise in order. Offset Paths uses its outline offset with the join (miter limit turned into a minimum angle, round as arcs); Copies make further rings at amount x (k + 1 + Copy Offset); open paths are offset point by point along their normals. The results are polygons, not curves.
- **Pucker & Bloat** moves each vertex toward the path's centroid by the amount and each control point the other way, so +100 collapses corners into a flower and -100 throws them out into spikes. **Twist** samples the path about every pixel and turns each point about Center by Angle x (1 - distance / the farthest point's distance). **Zig Zag** samples Ridges + 1 points per segment and pushes them alternately along the normal by Size, joined straight (Corner) or with handles a sixth of the neighbour span (Smooth). **Wiggle Paths** samples Detail points per segment and moves each by value noise (a shared track mixed with a per-point one by Correlation), Wiggles/Second and the phases moving it; seeded by the item uid so copies differ. **Wiggle Transform** gives each path (each Repeater copy) a translate, rotate and scale about its anchor from the same kind of noise.
- **Strokes**: up to three dash and gap pairs (`dash`, `gap`, `dash2` ... `gap3`, `shape.dashes.add` and `remove`). Taper (Start and End Length in pixels or percent, Start and End Width, the two Eases) and Wave (Amount, Units in pixels or cycles, Wavelength or Cycles, Phase) turn the stroke into a filled outline built here: the path sampled every 0.2 px, the half width at each sample from the taper ramps (smoothstep blended in by Ease) times 1 - Amount x (0.5 - 0.5 sin), offset along the normals both ways, round caps as half circles. Closed paths give two rings filled non-zero. Dashes are not applied to a tapered stroke.
- **SVG** (`render/svg.rs`, `usvg` without its text feature): paths with their absolute transforms, solid and gradient fills and strokes (gradient points mapped through the gradient and path transforms), dashes, caps, joins, paint order and group opacity. SVG files import as Vector footage (`FootageKind::Vector`), drawn as vectors at any scale and cached by path and modification time. `clipboard.pasteSvg` (the interface's paste of SVG text, and the Python `paste_svg`) builds a shape layer centred on its artwork, one group per SVG path.
- **Layer > Create** (`layer.create`): Shapes from Text makes a shape layer with one group per character (its contours, the character's fill and stroke) and the text layer's transform, and turns the text layer's video off; Masks from Text makes a comp-sized solid with one mask per contour in comp space, the first Add and the rest Difference so counters stay open; Shapes from Vector Layer does the same as the first for SVG footage.
- **Pen tool**: `mask.new` and `mask.addVertex` (the viewer's pen on footage and solids) and `shape.newPath` (on a shape layer, or a new one when nothing is selected; comp-space points are mapped into the layer) were missing from the engine before 0.14.0.

## Layer styles, time and keyframe assistants (0.15.0)

- **Layer styles** (`render/styles.rs`): a root group `layerStyles` after Transform holds Blending Options (Fill Opacity, Blend Interior Styles) and one group per style in After Effects' order. A layer with an enabled style always takes the buffer path in `layer_tile`, its pad grows by the largest outward reach (shadow distance plus twice the size, glow size, outside stroke, outer bevel), and `styles::apply` runs after the effects on the layer buffer in layer pixels times the buffer scale. Order: Fill Opacity scales the layer's own pixels; then the interior styles (Gradient Overlay, Colour Overlay, Satin, Inner Glow, Inner Shadow) blend into the unpremultiplied colour by their mode and coverage; Bevel and Emboss shades a height field (exact Euclidean distance to the edge over Size, inside for inner styles, outside for Outer Bevel, softened) lit from Angle and Altitude; Stroke goes over (outside, inside or centred, from the distance fields); Outer Glow and Drop Shadow go under. Drop Shadow's Layer Knocks Out removes the shadow under the layer's own alpha, which only shows once Fill Opacity is below 100. Use Global Light reads the composition's `global_light` (angle, altitude), set by `layer.style.globalLight`.
- **Time remapping** is a root property `timeRemap` (seconds of source time, keyed in layer time) inserted first. `Eval::source_time` reads it, and footage frames, precomp time and footage audio (interpolated per audio block) all go through it; expressions reach it as `timeRemap`. Enabling it keys the in point to itself and the last frame before the out point to itself. Freeze Frame replaces the keys with one hold key at the current time's source time; Freeze On Last Frame holds the source's last frame and extends the out point to the comp's end.
- **Time stretch** keeps the hold point (in, current time or out) fixed: the layer time there is kept and the start time solved from it; in and out points follow and swap when the stretch goes negative. Time-Reverse negates the stretch and moves the start to in + out - start, so the bar stays put and the keys (in layer time) reverse with the footage.
- **Responsive Design** (`responsive_time` in `render/comp.rs`): protected marker regions in a precomp keep their speed when the precomp layer is stretched, and the free time between them takes up the rest. `comp.responsiveTime` adds the protected marker for an intro (start to now), an outro (now to end) or the work area.
- **Frame blending** mixes the two nearest source frames (Frame Mix) when the comp switch and the layer's are on; Pixel Motion blends the same way until the flow field arrives with tracking. **Quality**: Draft samples nearest-neighbour through a thread-local flag in `warp`, Wireframe draws the content bounds as a one-pixel outline.
- **Roving keys** redistribute the times of the keys between the first and last non-roving keys by arc length along the motion path (`roving_times`), baked when `keys.interpolation` changes roving.
- **Keyframe assistants** (`engine/cmd/keytools.rs`): the Wiggler adds keys at Frequency per second between the first and last selected keys of a property, offset by seeded noise (jagged, or smooth as a 1-2-1 blend of neighbours) per dimension, the same for all, or on one; Temporal moves the sample time instead. The Smoother is a Douglas-Peucker pass on the selected range in property units, the kept interior keys turned auto Bezier. Motion Sketch takes pointer samples (comp space, mapped through the inverse parent transform), one key per frame, then the same simplification at the Smoothing tolerance. Exponential Scale keys every frame between two Scale keys with s0 (s1 / s0)^u. Convert Audio to Keyframes makes an Audio Amplitude null with Left, Right and Both Channels sliders keyed per frame over the work area (RMS x 100 of the comp's mix).
- **Separate Dimensions** adds X, Y and Z Position after Position and hides Position in the tree (`Eval::position` reads the three); merging keys Position at the union of their key times.
- **Markers** carry a URL, a frame target and a cue point (name, navigation, parameters) as well as chapter, duration, label and protection; `markers.set` edits by index or comp time or makes one, `markers.convert` moves one between the comp and a layer, `markers.nested` lists a precomp's markers at their times in this comp.
- **Dependencies** (`engine/cmd/deps.rs`): Collect Files writes `<project> folder/` with the project, a Footage folder (name clashes numbered) and a report; Consolidate merges footage items with the same file and interpretation; Remove Unused drops unused footage and solids; Reduce Project keeps the selected comps (or the active one) and what they use.
- **Animation presets** are a `formvfx.preset/1` JSON document (`.fvxpreset`): the selected effects and layer styles as groups, and the selected properties with values, expressions and keys relative to the first key. Applying renumbers the groups and offsets keys to the current time; the ten most recent paths fill Animation > Recent Animation Presets.
- **Viewer**: `view.takeSnapshot` renders the active comp at the current time into the engine state (served by `snapshot()` at `/api/snapshot.png`), `view.showSnapshot` toggles it; `view.splitLockedViewer` locks a second viewer to a comp and a 3D view. Shortcut presets keep each preset's overrides in the engine (`shortcuts.preset`, `export`, `import`).

## Effect catalogue and audio effects (0.16.0)

- **The host.** `FxCtx.host` is an `&dyn FxHost` the compositor fills (`Hx` in `render/comp.rs`): the layer buffer at another time with the effects above this one (`frame`), the buffer before any effect (`original`), this effect's parameters at another time (`param_at`), another layer as a buffer in its own frame with or without its effects (`layer`), another layer as it sits in the comp under this layer (`layer_in_comp`), a mask in buffer pixels, the audio of a layer or the comp, and the comp time, frame rate and stretch. `layer_buffer` rebuilds a layer's buffer up to a given effect index, so time effects (Echo, Posterize Time, Time Difference, Time Displacement, Timewarp, CC Wide Time, CC Force Motion Blur) see the frames below them only. Renders without a host (thumbnails, adjustment layers) fall back to the current values.
- **The effect frame.** Shape and text layers draw around their origin, so their effects work in a comp-sized frame centred on it (`fx_frame`): effect points are relative to its top-left corner and the buffer always covers it when an effect is on, so generators and particles reach the whole comp, as on a comp-sized layer in After Effects. Footage, solids and precomps keep their own size. Effect points on shape and text layers from 0.15.0 projects sit half a comp away from where they did.
- **Nested parameters.** `grp(id, name)` declares a group and parameter ids carry the path (`basic/temperature`), so Lumetri Color, Keylight and the CC set show their twirl-down groups; `params_at` flattens the tree back to those paths. Hidden string parameters (Curves' curves, the Liquify mesh) stay out of the tree.
- **Shared drawing** (`effects/draw.rs`): segment distance, coverage of a segment list, path fill and stroke from mask paths, polylines, trimming by length, `paint` over, on transparent or revealing the original, additive light, an FFT for Audio Spectrum, marching squares for contours. `util.rs` gained separable min and max (van Herk), unsharp, a triangle mesh rasteriser and grids for the warps.
- **Keying.** Keylight measures each pixel against the screen colour's dominant channel (screen gain and balance), then clips, shrinks, softens and despots the matte in its Screen Matte group, despills toward the bias and honours inside and outside masks; Color Range and the Lab-based keys use `to_lab`; the chokers are min/max passes with a soft threshold; Key Cleaner smooths the alpha only where it is partial, at the edge radius.
- **Colour.** Curves keeps each channel's curve as a hidden "x,y x,y" string evaluated through a monotone cubic into a 1024-entry table; Lumetri Color runs Basic Correction, Creative, Curves, Color Wheels, HSL Secondary and Vignette in that order on unpremultiplied colour.
- **Distortion.** Mesh warps (Bezier Warp, Mesh Warp, Warp's fifteen styles, Reshape, CC Power Pin) go through one triangle mesh rasteriser. Liquify keeps a 48 x 48 offset mesh as a hidden string; `liquify.stroke` applies the tool along the points (layer pixels) with the effect's brush, keyed when the mesh is animated, and `liquify.clear` empties it.
- **Simulation** is deterministic per frame: every particle is born at a fixed index from a hash of the seed, so frame n never depends on frame n - 1 and renders split across threads and machines agree. Paths are closed form (velocity with resistance as (1 - e^(-kt)) / k, gravity as t squared); CC Particle World projects through its camera and sorts by depth. Shatter and CC Pixel Polly cut the layer into cells (squares, bricks, triangles, hexagons, jittered glass) and move each by the force field.
- **Audio effects** (`effects/audiofx.rs`) pass video through and are skipped by `effects_on`, so a layer with only audio effects stays on the vector path. The mixdown (`render/audio.rs`) reads each layer's source into a buffer that starts `preroll` seconds early (the delay's echoes, the reverb's tail, the dynamics' release; at most 8), runs the chain in 256-sample blocks with the parameters at each block's time, and keeps the tail, so preview chunks, export and Convert Audio to Keyframes agree to within 1e-4. Filters are the cookbook biquads; Reverb is eight damped feedback combs into four all-passes per channel; Compressor is a stereo-linked peak envelope with a soft knee and a program-dependent release; Backwards reads the source mirrored about the layer's in and out points before the chain. Tone adds its oscillators to silence, so any layer with Tone is audible; applying it turns the layer's audio switch on and gives it Audio Levels.

## 3D (0.17.0)

- **Property ids follow the documented paths**: Camera Options `dof` (was `depthOfField`), Material Options `specularIntensity` and `specularShininess` (were `specular` and `shininess`), with `lightTransmission`, `metal`, `appearsInReflections` and `reflectionIntensity` added and Casts and Accepts Shadows as Off, On, Only; Light Options gained `falloffDistance`, the Environment type, `source` and `environmentRotation`. 0.16.0 projects keep their old ids and render those settings at their defaults; `.ecproj` imports now land on the right ids.
- **Lighting a layer** happens after its warp, per output pixel: the inverse of the layer-to-screen homography gives the layer point, the world matrix the 3D point, and the inverse transpose the normal (turned toward the viewer, as layers are two-sided). Classic terms: colour times (ambient lights times Ambient plus diffuse lights times Diffuse) plus specular times Specular Intensity, coloured between the light and the layer by Metal; the exponent is 2 + Shininess squared / 5. Falloff None, Smooth (from Radius over Falloff Distance) and Inverse Square Clamped; spot cones smooth from the outer half-angle to the feathered inner one. A composition without lights leaves layers unlit, as After Effects does.
- **Shadows.** A layer that casts is kept as a flat buffer (effects and masks included, at most 1024 px); a receiving point is tested against each caster by intersecting the segment to the light with the caster's plane and sampling its alpha, so soft edges and Light Transmission (the caster's colour let through) come for free. Shadow Diffusion jitters the light over a disk with nine taps. Models cast through shadow maps: one orthographic 1024 map fitted to the casting meshes for parallel lights, one perspective map over the cone for spots, six 512 faces for points, with a depth bias that grows with distance and a 3x3 or wider percentage-closer filter. Casts Shadows Only keeps a layer out of the image but in the casters; Accepts Shadows Only draws just the darkening on a layer (models treat it as On).
- **Models.** glTF 2.0 (JSON with data URIs or files, and GLB) and OBJ with MTL are read here (`render/model3d.rs`): node transforms flattened into the meshes, base colour factors and textures, metallic, roughness, emissive, triangle strips and fans, flat normals when a file has none, cameras and KHR_lights_punctual lights for Create Cameras and Lights from 3D Model. A model arrives 500 px across its largest side, centred on its bounds, with Y and Z flipped from glTF's Y-up into formvfx's Y-down space; the footage item records that size. The layer kind is Model, with Material Options that can override the file's materials. Primitives are Model layers with an animatable Geometry group instead of a source.
- **The rasteriser** (`render/mesh.rs`) clips triangles at a near plane, bins them into 16-row bands rendered in parallel, keeps the nearest fragment per sample (perspective-correct barycentrics) and shades each sample once; 2x2 supersampling below about 2.5 million pixels. Shading is physically based (GGX, Smith, Schlick) with lights treated as radiance 1 at 100%; without any light other than ambient a model gets a soft headlight so it is never black.
- **Environment.** An Environment light's Source layer (or else an Environment Layer) is rendered flat and resampled into a 512 x 256 equirectangular map with three blurred levels; roughness picks between levels, the most blurred serves as irradiance. Up is -Y. The background layer (`light.environmentBackground`) draws the map through the view's camera rays.
- **Depth of field** uses the circle of confusion aperture x |z - focus| / z x Blur Level at each pixel of the warped layer (or the model's depth buffer) and blends four Gaussian levels, growing the layer's tile by the largest radius so blur spills past its edges.
- **Advanced 3D** composites each run of 3D layers per pixel: every layer of the run gives its tile and a depth per pixel, and the fragments are sorted far to near. Blend modes, track mattes and motion blur inside such a run are not applied yet; Classic 3D keeps them.
- **3D views** are cameras kept per composition in the engine state, not in the project: Front, Left, Top, Back, Right and Bottom are orthographic (their zoom is a scale), Default and the three Custom views perspective. Frame requests and overlays take `view3d`; without it the composition's current view is used for display frames. Orbit, pan and dolly move the camera layer (keyed when animated, one undo step per drag) in Active Camera and the view camera elsewhere.

## Tracking (0.18.0)

- **Primitives** (`render/vision.rs`) are written from their definitions: a grey image per channel (RGB average, luminance or saturation) with 2x pyramids; normalised cross-correlation over a search window with a parabola fit for subpixel position; Shi-Tomasi corners with non-maximum suppression and a minimum distance; pyramidal Lucas-Kanade on 7 px windows; a dense flow that runs the same normal equations per pixel with blurred structure tensors, coarse to fine; least-squares fits from translation to homography (Hartley-normalised) and RANSAC with a fixed xorshift seed so results repeat.
- **What gets tracked.** `analysis::Source` renders a layer's own buffer before its effects at at most 1920 px (1280 for the camera tracker, 960 for the Warp Stabilizer), so an effect that consumes the analysis never feeds it. Results are stored in layer pixels.
- **Jobs.** An analysis takes a snapshot of the project (`Arc<Project>` and `Arc<Media>`), runs on its own thread and returns a closure that writes the result; `tick` polls the threads and applies a finished one through `Engine::apply_step`, so it lands as one undo step even though it was computed off the engine thread. A stopped job is dropped; `wait: true` runs it inline for agents and the command line. The Tracker panel polls `track.status`, whose progress covers the track, mask, warp and camera kinds.
- **Trackers** live in a root `motionTrackers` group: a tracker holds its kind, the Position, Rotation and Scale switches, the target and its options as hidden properties, and one `trackPointN` group per point (feature centre and size, search offset and size, confidence, attach point and offset), so points address as `motionTrackers/#1/trackPoint2/featureCenter`. A point is found by NCC around its predicted position (the previous velocity), refreshed per the Options (adapt every frame, or when confidence drops below the threshold, or stop, or extrapolate). Apply writes Position, Anchor Point, Rotation and Scale keys to the target or the layer itself (stabilize), or a Corner Pin for the affine and perspective kinds.
- **Mask and planar tracking** fit the chosen model to KLT tracks of corners inside the mask, frame to frame, then re-align every frame to templates from the reference frame so error does not accumulate. Planar Track makes a Perspective tracker named Planar Tracker, a Corner Pin and Grow Bounds on the insert layer, in one undo step.
- **Face tracking** (`render/face.rs`) is classical: a YCbCr skin mask inside the previous ellipse (or the mask's bounds), its moments give the face ellipse; detailed features search the ellipse's local frame for the darkest region in each eye band and in the mouth band, measure how far each stays dark up, down and sideways (eye openness, mouth width and height), place the brows and nose from those, and so give the 23 Face Track Points and the 10 Face Measurements. Both effects are hidden from the menus and the catalogue; they hold keys only.
- **Warp Stabilizer** (`render/stabilize.rs`) tracks corners through the clip with a forward pass, fits a homography per frame (similarity when that fails) and accumulates it into the layer's motion, plus a 6 x 6 grid of residual motion for Subspace Warp. The analysis is stored as text in the effect's hidden `analysis`, parsed once per text into a cache. Everything else is decided at render time: Smooth Motion is a Gaussian over the motion with sigma = Smoothness x frame rate / 100, No Motion holds the first frame; Position smooths the centre, Position, Scale, Rotation smooths a similarity fitted to the frame corners (log scale, so Preserve Scale keeps the original), Perspective smooths the four corners, Subspace Warp adds the smoothed residual grid. Crop masks to the largest centred rectangle every frame keeps; auto-scale finds it by bisection, capped by Maximum Scale and Action Safe Margin; Synthesize Edges fills uncovered pixels from neighbouring frames warped by their own corrections, then feathers the seam.
- **3D Camera Tracker** (`render/camsolve.rs`): features are tracked with a forward and backward check and replenished as they leave. The solve picks the frame pair with the most parallax (the 80th percentile of the residual after a homography, since a scene dominated by one plane leaves the median near zero). A tripod pan is recognised when the homographies of the longest pairs are rotations for some angle of view (`K^-1 H K` near orthogonal); then rotations are chained frame to frame by Kabsch on bearing vectors and points sit on a sphere. Otherwise the angle of view comes from the essential-matrix condition (the two leading singular values of `K^T F K` equal, over several pairs) unless it is specified, and the pair is started both from the essential matrix (Typical) and from the homography decomposition (Mostly Flat Scene); the one with the lower two-view error after refinement wins and is reported as Method Used. Frames are then added outward from the pair: each camera is refined from its neighbour against the points it sees (Levenberg-Marquardt with a Huber loss, numeric Jacobians, the focal length free per frame for Variable Zoom), new points are intersected when they have at least a degree of parallax, and the whole set alternates resection and intersection four times; a fixed angle of view gets a final golden-section refinement. Deleted points stay in the effect and the next solve skips them.
- **Placing the solve.** The first solved camera becomes formvfx's default camera: at (w/2, h/2, -zoom) looking down +Z, with the scale chosen so the points' median depth sits at the zoom distance (one pixel per unit there). The layer-to-composition scale turns focal lengths into zoom. Set Ground Plane and Origin fits a plane to the chosen points and rotates and moves the world so it becomes the XZ plane through the origin with up at -Y; the camera is re-keyed. The camera is a one-node camera keyed per frame on Position and Orientation (unwrapped so it never spins the long way) and on Zoom when it varies. Created layers sit on the plane fitted to the selected points, facing the camera, sized so Target Size 100 is 15% of the frame width at that depth; a shadow catcher accepts shadows only and adds a point light when the composition has none.
- **Masks.** Feather points (segment, position along it, radius, tension) are kept per mask as hidden JSON; the radius at a point of the outline interpolates between neighbouring feather points around the path, eased by their tension. After the hard coverage, each pixel within the largest radius finds its nearest outline point through a grid of the flattened outline: outward radii fade the outside, inward radii fade the inside, with a smoothstep or linear falloff, then the uniform feather blurs as before. Mask motion blur On averages the coverage over the shutter when the layer has none; Off evaluates the mask at the frame time inside the layer's motion blur. Smart Mask Interpolation matches vertex counts by splitting the longest segments, optionally rotates the second shape's vertex order to the closest match, and keys in-betweens at the composition rate: Linear Vertex Paths lerps, otherwise a similarity (rotation, log scale, translation) is interpolated and the residual added, mixed with the linear shape by Bending Resistance.
- **Pixel Motion** computes dense flow between the two source frames at at most 640 px (cached per frame pair while both frames are cached) and blends the two frames each moved part of the way along it.

## Roto, paint, puppet and Content-Aware Fill (0.19.0)

- **MobileSAM, written here.** The checkpoint is the official `mobile_sam.pt` (a zip of stored entries with a pickled state dict); `render/ptload.rs` reads the zip's central directory (zip64 included) and runs just enough of the pickle machine (dicts, tuples, globals, persistent ids, `_rebuild_tensor_v2`) to gather each tensor's storage, offset, size and stride. `render/sam.rs` then follows the published architecture: the TinyViT encoder (a two-convolution stem, MBConv blocks, patch merging whose last stage keeps stride 1 so the output stays 64 x 64, window attention with per-head biases indexed by the absolute offset between window positions and zero padding before the attention's own LayerNorm, a depthwise local convolution and an MLP per block) and the neck; the prompt encoder's random Fourier positions; the two-way transformer mask decoder whose first self-attention replaces the tokens rather than adding to them, the transposed-convolution upscaling and the hypernetwork heads. Batch norms are folded into their convolutions at load. Checked against ONNX Runtime running an independent export of the same model: embeddings agree to 3e-6, low-resolution mask logits to 7e-4, IoU predictions to 2e-6. The matrix products use an AVX2 and FMA kernel (4 rows by 16 columns in registers) when the processor reports both, else a blocked portable loop; an embedding takes about 2 s on two cores.
- **Roto Brush.** Strokes (frame, kind, radius, points), the span and the mattes live in the effect's hidden properties; a matte is binary at the analysis size (at most 1024 px), run-length coded with varints in base64, so a frame costs a few hundred bytes. The edge is made at render time: the binary matte is upsampled and passed through a guided filter on the frame's luminance (radius from Base Refine Edge Radius, larger with Render Refine Edge), then Feather, Contrast and Shift Edge, and Reduce Chatter averages with the neighbouring frames' mattes. Classic segmentation learns colour clusters for the object and the background from the strokes (and, when propagating, from the anchor frame's matte, never from the propagated guess, which would let uncovered background leak in), combines them with the warped prior by Bayes' rule and solves an edge-aware smoothness problem by conjugate gradients; small islands are dropped and small holes filled. With MobileSAM, stroke points become positive and negative prompts (thinned so one click is one point, letting the best of the three masks be chosen), and propagation prompts with the box of the warped previous matte, its interior points and the warped matte as mask input; a result that disagrees badly with the warped prior keeps the prior. Propagation runs from each frame with strokes to the next one, both ways, as one background job; a stroke starts it automatically over 20 frames each side unless Auto Propagate is off.
- **Object Matte** runs off the engine thread (`ObjectJob`): the frame's embedding is cached, so moving the pointer costs a decode (about 0.15 s); it returns the mask as runs with its origin and step in layer pixels, the box, the coverage and the model's IoU estimate. A click is a one-point Roto Brush spanned over the layer and propagated.
- **Paint** strokes are groups inside the Paint effect, so every stroke property animates and undo is ordinary. A stroke renders as dabs spaced along its path between Start and End; a dab is an ellipse (Roundness, Angle) whose edge falls off with Hardness; Flow accumulates coverage dab by dab and Opacity caps it; pen pressure scales size, opacity or flow per vertex when the dynamics ask. Clone strokes copy from the source layer (or this layer before its effects) offset by Clone Position minus the first point, optionally at another time; Aligned keeps the offset between strokes. Erasers remove the layer and paint, only paint, or only the previous stroke (kept unmerged until the next stroke so it can be erased alone). Write On keys End from 0 to 100 over the drawing time.
- **Puppet** meshes the outline of the layer at the mesh's time on a grid whose spacing gives about Triangles x Density / 10 triangles over the dilated alpha (Expansion), keeping the grid cells connected to where the first pin was placed. Deformation is as-rigid-as-possible: local rotations per vertex from its one-ring, a global Laplacian solve by conjugate gradients with pins as stiff constraints, ten rounds. Advanced and Bend pins impose their rotation and scale on the vertices around them; Starch pins raise the edge weights around them; Overlap pins give the triangles near them a depth, and triangles are drawn far to near with a per-pixel depth test so a fold shows the side in front. A new pin on a deformed mesh is placed at the rest position under the click.
- **Content-Aware Fill** reads the layer twice per frame, with and without its masks: what the masks remove is the hole, grown by Alpha Expansion. Frames are aligned by homographies between neighbours from corners outside the holes, chained to the first frame. Object fills each hole pixel from the nearest frame in time where that spot is uncovered; Surface takes the whole hole from the nearest frame that covers it all; Edge Blend interpolates from the hole's edge (pull-push then relaxation). The temporal fills are blended into the frame by interpolating the difference along the hole's border across the hole (Lighting Correction scales how much of that difference is spatial rather than one average). The result is written as a PNG-coded movie with alpha only in the hole and added above the layer.

## Colour management, OCIO, GPU and the disk cache (0.20.0)

- **One operator list for every conversion.** A `Proc` is a list of `Op`s (matrix with offset, power with a negative style, moncurve, log, log affine with an optional camera break, CDL, range, 1D and 3D LUTs, fixed functions, an ACES output transform). formvfx's own profiles (`color::SPACES`), OCIO configs and LUT files all compile into it, so the pipeline, the effects and the GPU see one shape. `Proc::new` folds neighbouring matrices.
- **The project pipeline** (`color::Pipe::of`) is rebuilt per render from the settings. Pixels live in the working space's encoding, or linear when Linearize is on or the space is linear. Authored colours (vector content and effect colour parameters through `FxCtx::c`) are the working space's numbers; with Linearize they are decoded, and with the OCIO engine they are the `color_picking` role's numbers converted to the working space. Lumetri's wheels and the other neutral-grey controls read `c_raw`, since they are offsets, not colours. Footage converts from its profile (Interpret Footage, else the transfer FFmpeg reports, else sRGB) and the result is cached against the decoded frame. Blend Colors Using 1.0 Gamma decodes each tile and the canvas around the blend; adjustment layers see the working encoding. 8 and 16 bpc quantise after the source, every effect and every composite, the way an integer pipeline would; 32 bpc keeps over-range values.
- **Display and output** are the last step: the viewer frame is flattened over the background (converted like any authored colour), then sent through the display proc (display profile, Simulate Output with or without Preserve RGB, Tone Map for over-range values in 32 bpc); the Render Queue sends frames through the output space's proc and writes 16-bit data where the format holds it. PQ and HLG map 1.0 to 203 nits (BT.2408 reference white).
- **OCIO** configs are read by a YAML subset reader (block and flow collections, tags, block scalars) and kept as transforms until a processor is asked for; unsupported builtins are errors only when used, so a studio config with camera transforms loads. Scene and display reference spaces follow OCIO 2: crossing them uses the config's default view transform; a view with a view transform goes source, looks, scene reference, view transform, display colour space. The ACES 1.x output transforms (glow, red modifier, the RRT spline, the 48-nit ODT spline, dim surround, the SSTS for HDR with its exposure shift, the limiting gamut) and the 1.3 gamut compression are written from their definitions; checked against OpenColorIO 2.6 on the ACES 1.3 CG and studio configs: forward transforms agree within 0.2%, inverses of HDR output within 2% where OpenColorIO itself approximates with curves. Differences found on the way, now matched: Display P3 mirrors negatives, the cinema ODT has no saturation step, the 1.1 SDR limits clamp after the white-point adaptation, Apple Log uses Rec. 2020 primaries, inverse output transforms clamp to the limiting gamut and to zero in AP0.
- **GPU.** The device is opened in the engine only after the service's out-of-process probe succeeded. Images are storage buffers of float RGBA, so the kernels can mirror the CPU code exactly: the warp plan (`gpu::plan`) repeats `image::warp`'s bounding box and mip decision, the composite kernel samples bilinear or nearest with the same edge rules and runs the same blend formulas and quantisation. A layer's effects run on the CPU up to the last effect the GPU cannot do; the rest run on the GPU as box passes or a pointwise program (a small interpreter over the encoded operators, so the OCIO transforms whose operators are all portable come for free). Layers the GPU path does not take (3D with a camera, motion blur, track mattes, models) are made on the CPU and uploaded as tiles; adjustment layers download the canvas, run on the CPU and upload it; Dissolve, Advanced 3D and 1.0-gamma blending keep the whole composition on the CPU. Auto renders a composition twice on each and keeps the faster, measuring again every 240 frames.
- **Disk cache.** The key is a SHA-256 over the composition's closure (the comp, its precomps and items, the project settings, footage size and modification stamps, LUT and config stamps; the whole project when an expression names another comp or footage) and the frame request (time, scale, view, channel, display). Only frames that took 40 ms or more are written. Eviction removes the oldest files when the folder passes its limit.

## Formats, proxies, the Render Queue and Lottie (0.21.0)

- **Readers and writers.** OpenEXR goes through the `exr` crate (its compressions are a project of their own); Photoshop is read and written here (`render/psd.rs`: header, layer records with Unicode names, section dividers for groups, user masks, raw, RLE and both zip modes at 8, 16 and 32 bits, the merged image, the 16 and 32-bit layer blocks in the global section); PDF and PDF-compatible Illustrator pages are drawn by `hayro`, whose standard fonts come from PDFium. A PSD written by an ImageMagick Q16 build declares 16 bits and stores 8; psd-tools rejects it too, so it is not read.
- **Footage keys.** A footage item can name a Photoshop layer (index and name), an EXR layer (name), a PDF page and whether a Photoshop layer keeps its own size; stills are cached under all of them. Numbered stills become a sequence when a second file with the same prefix and extension sits beside them (`sequence: false` keeps one still); sequence frames go through the frame cache with its memory budget, not the stills cache. EXR footage is marked scene-linear: managed projects convert it like any profile, unmanaged ones show it sRGB-encoded.
- **Photoshop as a composition.** Groups become nested compositions at document size; pixel layers become footage items of one layer, at document size or (Retain Layer Sizes) at their own size, placed at their rectangle. Blend modes map by key, Pass Through to Normal; a clipped layer gets Preserve Underlying Transparency, which equals Photoshop's clipping when the base is the layer below.
- **Layered frames.** Save Frame As Photoshop Layers and Layered EXR render each visible layer alone (solo, Normal, 100%) and the merged frame; the PSD keeps the blend mode and opacity on the layer record and crops each layer to its pixels, the EXR stores the composite as R, G, B, A and every layer under its name, scene-linear and premultiplied.
- **Proxies** live on the project item (footage or composition) as a footage of their own with an on switch. The renderer draws the proxy at the original's size by scaling its sampling density, so the layer's transforms and effects see the original's coordinates. Render Settings Proxy Use is applied to the queue's copy of the project, never to the open one.
- **Render Queue.** An item has Render Settings and one or more output modules; frames are rendered once and handed to every module, which crops, resizes, picks channels and colour, then writes a sequence, an FFmpeg pipe or an audio file. Templates are built in plus a user file in the data folder (`render-templates.json`) with defaults per slot (movie, still, pre-render, proxies); a change to an item without a template name marks it Custom. Field rendering interleaves two renders half a frame apart and pads the height to a multiple of four for 4:2:0; 3:2 pulldown maps four source frames to five output frames by the chosen phase. Items from 0.20 projects are read into one output module. Post-render actions run on the engine thread when the render's result is collected.
- **Lottie.** Export writes keyframes with their temporal ease as Lottie's bezier handles (influence is the handle's x, speed times influence over the value change its y; spatial keys ease over the arc length, as here), bakes expressions per frame unless asked to keep them, embeds still footage as PNG, and puts a track matte's layer directly above the layer it mattes (a copy with `td` per user) because classic players only look one layer up. Shape objects are written with `ty` first: rlottie reads the type before the other keys, and a last keyframe with handles stops its animation. Checked against rlottie on shapes, eased and baked motion, parenting, masks, mattes, precomps and text outlines to within a pixel. Import reads the same subset back (split positions are sampled per frame) and a `.lottie` archive's first animation.

## Scripting, ScriptUI and the expression additions (0.22.0)

- **One interpreter for both.** Scripts run on the expression interpreter with `script` set: the step limit rises to 400 million, names resolve through `expr/script.rs` before the expression builtins, and host handles (`H::App`, `H::Project`, `H::Items`, `H::Layers`, `H::Window`, `H::Control` and the rest) are answered by the script object model instead of the expression one. A second JavaScript engine would have meant a second object model to keep in step; sharing the interpreter keeps vector maths, `JSON` and the string methods identical in expressions and scripts.
- **Reaching the engine.** A script mutates the project, so it cannot hold the `Arc<Project>` an expression reads. `script::exec` parks `cx.project` on a dummy, keeps a raw pointer to the `Engine` in a thread local for the length of the run (the engine thread is the only thread that runs scripts), and every setter goes through `Engine::execute` with the command a person would use. After each command `sync` points `cx.project` at the live project again, so reads after writes see the change. Commands made by a script run inside `cmd::script::guarded`, which raises `batch_depth`, so the whole run is one undo step named by `app.beginUndoGroup` or the file name.
- **The object model.** Items, compositions, footage, folders, layers (`addSolid`, `addText`, `addBoxText`, `addNull`, `addShape`, `addCamera`, `addLight`, `add`, `byName`, `precompose`), property groups (`addProperty` for effects, masks, text animators and shape items, with match names and their ADBE aliases), properties (`setValue`, `setValueAtTime`, keys, eases, interpolation, expressions) and the Render Queue. `layer.property("Source Text")`, `Marker` and `Time Remap` are found below the transform group, as in After Effects. A nested shape group passes its parent's uid so `addProperty` lands inside it. `Date` follows the civil-from-days algorithm; `File` and `Folder` read and write through the standard library with the usual open, read, readln, write and close.
- **ScriptUI.** Windows and controls live in a thread-local store with their handler closures; the engine emits `scriptui.show` with the whole tree and the interface sends `scriptui.event` back, which runs the handler as its own undo step. Dialogs do not block: `show()` returns 1 at once, so a dialog's work belongs in its handlers. Panels are scripts in `Scripts/ScriptUI Panels`, listed in the Window menu; installed scripts are listed under File > Scripts.
- **Regular expressions** use `fancy-regex` (MIT), which has the look-around and backreferences JavaScript patterns rely on. The lexer reads a regex literal where an operand may start (after an operator, an opening bracket, a comma or a keyword) and the parser turns it into `new RegExp(pattern, flags)`. Compiled patterns are cached by pattern and flags; `g`, `i`, `m`, `s` and `y` are honoured, `lastIndex` with `g` and `y`.
- **`sampleImage`** renders the sampled layer through a `Renderer` built on the shared media (`render::media::share` keeps a weak handle the expression host can reach). Post-effect samples render the whole layer; pre-effect samples render only the sampled rectangle with masks. A thread-local depth guard allows one sample inside another and refuses a third, so a chain of `sampleImage` calls that comes back to its own layer ends with an error instead of recursing.
- **The text style API.** `text.sourceText.style` and `getStyleAt` return a style object; each `set*` returns a changed copy that records which fields changed (or, with a start and end, a character range). Returning it from a Source Text expression applies only the recorded changes to the document, so a style read and returned untouched changes nothing.

## Render passes, Essential Graphics, plug-ins and the learned face tracker (0.23.0)

- **Auxiliary channels.** `exr::read_aux` keeps every channel of an EXR (named with its part) and its string attributes; `Media::aux` caches the last eight files and picks the sequence frame for the layer time. The effects reach them through `FxHost::aux`, which has a default of none, so only the compositor's host answers and only for footage layers. A pass is sampled nearest-neighbour at the source pixel under each buffer pixel, as 3D applications intend for ids and depth; 3D Channel Extract's Anti-alias smooths the result afterwards. Channel names are found by convention (`Z`, `depth.Z`, `objectId`, `IndexOB`, `N.X`...) and by suffix, because every renderer names them differently; EXtractoR and IDentifier take any name.
- **Cryptomatte** follows the public specification: the manifest maps names to ids, ids are MurmurHash3 (x86, 32-bit, seed 0) of the name with the exponent bits kept away from 0 and 255, ranks are pairs of id and coverage in `name00.RGBA`, `name01.RGBA`... The hash was checked against the `mmh3` package; a name missing from the manifest is hashed directly, and `<hex>` selects an id.
- **Depth of Field** blurs five levels of the layer and blends between the two around each pixel's radius, rather than a true variable-radius gather; it is fast and has no halos at the focal plane. Camera-Shake Deblur replaces a frame that is markedly less sharp (variance of the Laplacian) than its sharpest neighbour within Blur Duration with that neighbour warped onto it by optical flow; Rolling Shutter Repair moves each row by the flow times its scan offset; Pixel Motion Blur averages samples along the flow over the shutter.
- **Essential Graphics.** Controllers live on the composition (`Comp::essential`): property controllers point at a layer id and a property uid; comments and groups have no target. Instances are precomp layers; `cmd::essential::sync` runs inside every undoable change (before the step is recorded) and keeps each instance's `essentialProperties` group in step: names, UI and the master value as the property's `default`. An instance property is overridden when it differs from that default or has keys or an expression; the renderer then renders the nested composition from a patched copy of the project (`render::essential::patched`), so expressions, `sampleImage` and the disk cache see the override like any other value. Layer ids and property uids change when a composition is duplicated or a project imported, so controllers are remapped by property path there.
- **Templates** are a zip (the Lottie writer's) holding `template.json` (the format, the controllers and the reduced project), a poster PNG and `media/`; footage paths become file names and are rewritten to the extraction folder on import, which then goes through the ordinary project import.
- **Plug-ins** run on wasmi (an interpreter, not a JIT: it builds everywhere, including the frozen desktop sidecar, and fuel metering bounds every call). A fresh instance per render keeps plug-ins stateless and thread-safe; parameters cross as JSON so the ABI needs nothing but memory, `fvx_alloc`, `fvx_describe` and `fvx_render`. Plug-in effects are leaked into `'static` specs at load, which is what the effect registry and `EffectSpec` need, and they are found through `effects::every()` beside the built-ins.
- **TensorFlow Lite.** `render/tflite.rs` reads the flatbuffer by hand (tables, vtables, vectors) and runs the operators the face models use (convolution, depthwise convolution, pooling, PReLU, padding, reshape, concatenation, logistic) in float32 with float16 weights widened at load. It matches LiteRT to 2e-4 on both networks. `render/facemesh.rs` is the MediaPipe pipeline: SSD anchors for the short-range detector, weighted non-maximum suppression, a square crop rotated by the eye line and scaled 1.5 times, the 478-point mesh, and tracking from the previous frame's landmarks until the face score drops, then detection again.
